# 《工贼模拟器（Managing Up）》系统策划案 —— 办公室系统

| 项目 | 内容 |
|---|---|
| 所属游戏 | 工贼模拟器（Managing Up）· 2D 办公室题材放置/经营游戏（Godot 4） |
| 系统名称 | 办公室系统（Office System） |
| 文档版本 | v1.0（随游戏上线版本） |
| 状态 | 已实装并通过自测 |

---

## 1. 设计目标

| # | 目标 | 对应设计 |
|---|---|---|
| 1 | 给放置玩法提供**空间维度的策略**，而不只是堆人头 | 有限的房间格子 + 6 种功能 + 唯一性限制，构成配置题 |
| 2 | 让每次"改造"都是**有代价的取舍**，而非无脑全开 | 房间数量受职级限制；三种功能全司唯一；改造即刻覆盖旧功能 |
| 3 | 成长曲线要有**明确的阶段感** | 职级 M1→M6 逐级解锁功能、工位排数与工位上限 |
| 4 | 让办公室**看起来像个办公室**，承担叙事 | 房间三态视觉、功能图标、悬停交互、企业文化/炒股等职场符号 |

**一句话定位**：办公室是玩家把"人"转换成"产能"的容器，也是这家公司的组织结构图。

---

## 2. 房间三态

每个房间格子在任意时刻处于三种状态之一，底图与图标分别响应：

| 状态 | 房间底图 | 功能图标 | 可交互 |
|---|---|---|---|
| **未解锁** | 灰色不可用图 | 隐藏 | ✗ |
| **空置** | 空房间图 | 隐藏 | 点击 → 打开功能选择 |
| **已分配功能** | 已启用图 | 显示对应功能图标 | 点击 → 功能选择；悬停按钮 → 直达专属页签 |

> **实现要点**：底图（RoomTexture）与功能图标（RoomIcon）职责分离——底图表达"这个格子处于什么状态"，图标表达"它现在是什么功能"。二者由同一处状态刷新驱动，避免不同步。

---

## 3. 功能类型总表

| 功能 | 解锁职级 | 数量限制 | 核心作用 | 消耗货币 |
|---|---|---|---|---|
| 🍵 **茶水间** | M1 | 可设多间 | 每间 +1 全局零食名额 | — |
| 📈 **炒股办公室** | M1 | **全司唯一** | KPI 买卖股票；驻场分红产美金 | KPI |
| 🎯 **猎头办公室** | M3 | **全司唯一** | 解锁猎头招聘（高稀有度） | 美金 |
| 💬 **会议室** | M4 | 可设多间 | 效率换品质/经验 | — |
| 📚 **员工培训室** | M4 | 可设多间 | 停产换属性永久成长 | 机会成本 |
| 🎌 **企业文化室** | M5 | **全司唯一** | 全局属性 +2（三选一） | — |

**唯一性设计**：猎头、文化、炒股三者**全司唯一**，因为它们提供的是**全局效果**——若可叠加，会瞬间失去配置意义。茶水间/会议室/培训室提供的是**容量型效果**（名额、席位），因此允许多间，让"要几间"本身成为选择。

> UI 上通过 tooltip 首行明确标注「全司唯一 / 可设多间」，并在已存在时把按钮置灰 + 遮罩，避免玩家反复试错。

## 4. 各功能详细规则

### 4.1 茶水间 Pantry

- 每建成一间，**全局零食名额 +1**（`total_pantries`）。
- 员工每次开始新一轮生产时，若名额未满则 **80% 概率**申请零食，随机获得三种之一：

| 零食 | 效果 |
|---|---|
| 奶茶 | 效率 +2 |
| 蛋糕 | 品质 +3 |
| 烤肠 | 经验 +3 |

- **击鼓传花**：持有者用完（完成本轮/被打断/离场）后归还名额，并**随机**挑一名正在工作且未吃零食的同事接盘。
  > 采用随机挑选而非按场景树顺序，避免"永远是前排那几个人吃到"的阶级固化。

### 4.2 会议室 Meeting Room

- 最多 **6 人**同时参会；参会者占用原工位、隐藏真身，**仍然产出**。
- Buff：**效率 −1**，品质 +1~3、经验 +1~3，**每轮重新掷骰**。
- **1 小时**（游戏时间）自动散会；也可手动解散。
- 设计意图：唯一的"负和"Buff。牺牲确定收益换随机收益，与"开会到底有没有用"的现实体验同构。

### 4.3 猎头办公室 Headhunt

- 解锁猎头招聘入口，**消耗美金**（100 × 人数）。
- 概率：SSR 4% / SR 13% / R 83%；1 人 30 秒，10 人 270 秒。
- 设计意图：把稀缺货币（美金）与稀缺人才绑定，形成第二条独立于 KPI 的经济链。

### 4.4 企业文化室 Culture Center

- 三选一，全体员工对应属性 **+2**：效率 / 品质 / 经验。
- 可随时切换，**即时生效**（撤销旧的、应用新的）。
- 设计意图：一个"看起来很大、实际只能选一个"的全局增益，精准命中企业文化的空洞感。切换时同事会吐槽"画大饼，绝对是画大饼"。

### 4.5 炒股办公室 Trading

- 4 支虚拟股票：**996福报科技 / 画饼集团 / 韭菜农业 / 摸鱼网络**。
- 以 **KPI** 买入卖出，记录加权平均成本与盈亏；提供全买/全卖。
- **驻场分红**：定时产出**美金**，是美金的第二条来源。
- 设计意图：给 KPI 一个"高风险再投资"的出口，让玩家在"稳定攒"和"赌一把"之间选择。股票命名承担讽刺功能。

### 4.6 员工培训室 Training Room

- 最多 **5 人**；选一项属性 + 设定轮数（1~99），每轮 **10 分钟**。
- 每轮对每人独立掷骰：`P(+1) = (100 − 10 × 当前属性值)%`，属性封顶 10。
- **培训期间完全停产**——这是本作唯一的纯机会成本设计。
- 详见独立文档 `training_room_design.md`。

## 5. 改造机制

```
[空置房间] ──点击──> [功能选择面板] ──选择──> [已分配]
      ▲                                          │
      └──────────── 改造成其它功能 ───────────────┘
                （旧功能立即 cleanup，人员安全遣返）
```

- 改造**无冷却、无费用**，鼓励玩家频繁重构布局。
- 切换时旧功能执行清理：会议/培训室遣返全员回工位，茶水间归还零食名额，唯一性标志位释放。
- 面板顶部常驻**「当前功能：XXX」**状态行，正在使用的功能带选中描边 + 对号标记。

> **设计取舍**：不设改造费用，是因为本作的成长压力已经由"房间数量"和"职级门槛"承担。再加一层费用会让玩家不敢尝试，反而削弱这个系统最有趣的部分——**重新配置**。

## 6. 成长与解锁

### 6.1 职级 M1 → M6

| 升级 | KPI 花费 | 解锁 |
|---|---|---|
| M1 → M2 | 50 | 茶水间体系铺开、工位排数 +1、工位可升 2 级 |
| M2 → M3 | 5,000 | 猎头办公室、工位排数 +1、工位可升 3 级 |
| M3 → M4 | 30,000 | 会议室、培训室、工位排数 +1、工位可升 4 级（满） |
| M4 → M5 | 100,000 | 企业文化室、工位排数 +1 |
| M5 → M6 | 200,000 | 通关（结算场景） |

- **工位排数** = 当前职级
- **工位最高等级** = min(职级, 4)

> 花费呈**近似十倍阶跃**（50 → 5k → 30k → 100k → 200k），每一级都需要玩家重新优化产能结构才能跨越，而不是线性等待。

### 6.2 工位升级

| 升级 | KPI 花费 | 效果 |
|---|---|---|
| Lv1 → Lv2 | 200 | 效率 **+2**（换普通电脑） |
| Lv2 → Lv3 | 500 | 品质 **+2**（换高级电脑） |
| Lv3 → Lv4 | 1,000 | 纯外观（绿植） |

> Lv4 只给外观不给数值，是刻意的：让"把工位堆满"成为**玩家的自我表达**而非最优解压力。

### 6.3 楼层扩展

- 第二层由 `BuildingManager` 动态创建，进入**装修系统**（自由放置家具/房间，消耗 KPI，可变卖回收）。
- 切换楼层时对应楼层视觉整体显隐，相机记忆各楼层视角。

## 7. 交互设计

| 交互 | 行为 |
|---|---|
| 点击房间主区域 | 打开面板的「功能选择」页签 |
| 悬停房间 | 功能图标与底座**轻微下沉**并亮起描边；对应功能的专属按钮浮现 |
| 点击专属按钮 | 直达该功能页签（文化 / 炒股 / 培训） |
| 按下房间 | 图标额外下沉并压暗，给出"按下去了"的反馈 |
| 拖入员工 | 会议室 / 培训室接收；其余拒收并弹回 |
| 空置提示 | 空房间图标左右摇晃招手 |

> **设计要点**：主区域与专属按钮**分工明确**——主区域永远是"我要改功能"，专属按钮才是"我要用这个功能"。避免玩家想调整培训却每次都被塞进培训页。

## 8. 边界情况与异常处理

| 场景 | 处理 |
|---|---|
| 唯一功能已存在 | 该按钮置灰 + 遮罩，tooltip 说明「全司唯一」 |
| 职级不足 | 显示锁头图标，tooltip 提示所需职级 |
| 改造正在使用中的房间 | 旧逻辑 `cleanup()`：遣返人员、归还名额、释放唯一标志 |
| 会议/培训中的房间被改造 | 等价立即结束，全员安全回工位，不丢人 |
| 房间锁定状态 | `mouse_filter` 关闭，彻底不响应任何交互 |
| 读档 | 恢复每间房的解锁状态与功能类型；多间同类房间按路径精确还原人员归属 |
| 升级特效 | 读档时设置职级不播放"升级爆闪"，仅实时升级瞬间播放 |

## 9. 迭代记录（摘录）

| 迭代 | 内容 | 原因 |
|---|---|---|
| 房间视觉 | 所有贴图堆在图标上 → 底图与图标职责分离 | 原实现让"锁定/空置/功能"三态与功能图标抢同一个节点，导致空置房间仍显示上一个功能的图 |
| 培训室入口 | 点主区域直达培训页 → 悬停按钮直达 | 与文化室/炒股室交互不一致；且玩家想改造培训室时每次都被塞进培训页 |
| 悬停反馈 | 图标放大至房间大小 → 图标与底座一起轻微下沉 | 放大会拉伸变形，且底座不跟随，产生割裂感；下沉更克制，也更像"可按下的实体" |
| 选中标识 | `ReferenceRect` 黄色调试框 → StyleBox 空心圆角描边 + 对号 | 前者是编辑器调试节点，无圆角无样式，观感粗糙 |
| 唯一性提示 | 无 → tooltip 首行标注「全司唯一 / 可设多间」 | 玩家无法区分"点不了"是因为等级不够还是已经建过 |

## 10. 后续扩展（预留）

1. **相邻效应**：相邻房间产生组合加成（茶水间挨着会议室 → 会议不掉效率），把布局从"有几间"变成"怎么摆"。
2. **房间等级**：功能房自身可升级，提供比"多建一间"更深的投入曲线。
3. **改造冷却或费用**：若后期数据显示玩家频繁横跳、削弱了取舍感，可加入软性成本。
4. **更多职能办**：法务部（处理劳动仲裁事件）、行政部（影响事件概率）等，与事件系统联动。
