## 1. 制作人对新事件的要求（原话整理）

1. **选完之后要发生意料之外的事**，让玩家惊讶到沉默，或者直接笑出来；不是属性多一点少一点。
2. **要真实**，让玩家想到中国职场和自己的生活，"十分难绷"。
3. 事件系统**不方便直接去掉**，要在现有基础上改。
4. 文案得改；现在给的属性和后续处理也没意思。

## 2. 现状诊断（2026-11-02 时点）

### 2.1 数据

- 21 个事件，46 条群消息，42 个选项。定义在 `scripts/events/event_definitions.gd`（`const EVENTS`），文本在 `language/events.csv`。
- 每个事件只有两个字段：`messages`（文本 key 数组）、`options`（`{text, stat, amount}`）。没有 id、说话人、条件、权重、冷却、后续。

### 2.2 为什么没意思——三层原因

**一、根本没有"选择"。**
- 16 个事件两个选项**都是加 buff**，只是挑加哪个；5 个一正一负，负的那个谁都不会选。
- **没有一个选项有代价**。"下午茶我请""加班餐管够""庆功宴"都不扣钱。

**二、结果没有放包袱的位置。**
- 选完只弹一行灰字"全体员工 效率 +1（持续 3 分钟）"，不到一秒窗口就关（`event_chat_ui.gd:180-192`）。
- 没有人回话，世界里什么都没发生。**笑话靠反应，这个系统里没有放反应的地方。** 这是结构问题，文案救不回来。
- 数值也小：效率 +2 持续 3 分钟，每名员工约多出 20 KPI；招一个人要 750。

**三、文案是员工手册腔。**
- 「听说老板最近又裁了一个人。」把话题平铺直叙说出来，选项是"打鸡血"和"体谅"两种立场。
- 对比 `language/ingame_banter.csv` 的头顶吐槽：「补偿只有 N+0.1？」「掏香蕉的钱就只能请到猴子……」「干一个月没被优化就是胜利」——**那个味儿是对的。**

### 2.3 其他问题

- **头像**每个气泡随机换一个员工，且不显示名字 → 没有"谁说的"，没有角色。
- **玩家身份是乱的**：E07「老板请客不过分吧？」、E21「老板，您给句话吧」把玩家当老板；E02「老板脸都黑了」、E09「老板又开始讲愿景了」又在群里吐槽另一个老板。教程和头顶吐槽里，玩家是老板手下的项目负责人。
- **抽取**：完全均匀随机（`event_chat_ui.gd:71`），会连抽同一个；看全 21 个平均要两个半小时以上。与游戏内的天、昼夜、等级、房间全部无关。
- **不存档**：挂起的事件、buff、抽取历史都不存。
- 文本是纯 `tr(key)`，**不能带变量**（`event_chat_ui.gd:99, 110`）。
- 只有两个选项按钮，按钮文字就是玩家发言，二者分不开。

## 3. 设计方向

### 3.1 核心：标题已经说了每个事件该怎么写

**工贼**——站在老板那边出卖工友的人。玩家是夹在中间的那个：领导要的东西，得玩家开口在群里说。

所以每个事件都是一个**夹心处境**：两个选项**都会出卖某个人**，包袱是"怎么出卖的"。
不是"打鸡血 vs 体谅"，而是"出卖兄弟 vs 出卖自己"。

**先把身份定死**：玩家 = 项目负责人；群里另有"领导"这个角色。

### 3.2 写作要点

1. **具体**。3.25、N+1、"一对一沟通"、第二杯半价。数字和黑话比形容词好笑。
2. **用职场的"文体"**。"收到"刷屏、撤回了一条消息、@所有人、群公告、60 秒语音条、"在吗"、OA 审批流、离职邮件。形式本身就是梗，而界面本来就是群聊。
3. **包袱放在结果里，不放在问题里**。问题可以平淡，翻转留给选完之后。
4. **好心没好报，坏心偶尔有奇效**。体谅大家 → 被当软柿子；甩锅 → 锅甩回自己身上。
5. **用玩家自己的东西**（见 §5）。员工真名、项目名、持有的股票，尤其是**玩家自己写的催工台词和便签**——比如员工把玩家写的催工台词做成表情包在群里刷。"想到自己的生活"，字面意义上的。
6. **克制**。少用感叹号，平静地说荒唐的事。
7. **少而精**。十几个真好笑的，胜过四十个凑数的。分常见小事件和稀有大事件。

### 3.3 改写示例

**「背锅」**（原版：「责任我来担」效率+1 / 「谁的问题谁负责」质量+1）

> **领导**：上周线上事故，复盘会要定责任人，下班前给我一个名字。
> **小王**：……
>
> **A「责任我来担。」**
> **领导**：好，有担当。
> **领导**：这个月绩效你 3.25，大家向你学习。
> 〔你的美金 -500〕〔全体员工 效率 +1〕
>
> **B「谁的问题谁负责，查日志。」**
> **小李**：查了。
> **小李**：上线是你批的。
> 〔群里安静了〕

两个选项都打到玩家自己。

**「下午茶」**（原版：「我请，都点起来」效率+1，不扣钱）

> **小王**：楼下新开了家奶茶，第二杯半价
> **小李**：@{你} 老板～
>
> **A「今天下午茶我请，都点起来！」**
> **小王**：谢谢老板！！
> **小李**：谢谢老板！
> **小张**：谢谢老板
> **实习生**：统计了一下一共 23 杯。我们组 6 个人。
> 〔美金 -{23 杯的钱}〕
>
> **B「可以，但方案今天得交。」**
> **小王**：收到
> **小李**：收到
> **小张**：收到
> 〔小王 撤回了一条消息〕

"撤回了一条消息"成本最低、效果最好：玩家自己脑补撤回的内容。

**回旋镖（需要延迟后果）**：今天选了「年底一定帮你们争取」，三天后群里有人 @玩家："年底了。"

## 4. 代码改动分步（按性价比）

### 第一步：小改，解锁绝大部分效果
- 选项后加**结果消息**（放包袱的地方）；窗口等玩家看完再关。
- 每条消息带**说话人和名字**；同一个事件里同一个人保持同一个人。说话人可以是随机员工、固定角色（领导/HR/客户/实习生）或系统。
- 文本支持**变量**：`{员工1}` `{项目名}` `{股票}` 等（`tr(key).format(dict)`）。
- **系统灰字**扩展成通用的：「xx 撤回了一条消息」「群里安静了」「xx 修改了群公告」。现有 `_add_system_message` 可以直接复用。
- 效果接上**现成接口**：扣钱/加钱、单个员工永久加减属性、开除（升天动画现成）、发零食、送去开会、员工头顶冒吐槽（让世界在群聊之后也有反应）。
- **洗牌袋**：一轮没看完不重复。

### 第二步：中等
- **记忆（flag）+ 延迟后果**：选项写下一个标记；N 个游戏日后触发后续事件。需要存档。
- **随机分支**：同一个选项，七成 A 结局，三成 B 结局。
- **触发条件 + 权重**：有茶水间才出茶水间的事；员工多了才出派系的事；稀有大事件一局只出一次。

### 第三步：以后再说
- 事件数据从代码里挪出来，改成表格驱动，写文案的人不用碰代码就能加事件。

## 5. 游戏里已有、事件可以引用的东西

**能读的状态**
- `Gamemanager`：项目名、玩家等级、KPI、美金、总游戏时长、累计点击和催工次数、**玩家便签原文**（`sticky_note_text`）、手机电量、是否有招聘室/文化室/炒股室。
- `EmployeeManager.my_employees`：每个员工的**显示名（含玩家改的名）**、稀有度、三属性、在职时长、是否在摸鱼/漫游/开会/培训。
- `Ledger`：当前是第几天、各来源收支、每个员工的生涯 KPI。
- 房间：类型（茶水间/会议室/招聘/文化/炒股/培训）、是否解锁；会议室和培训室里有谁。
- `StockManager`：**996福报科技 / 画饼集团 / 韭菜农业 / 摸鱼网络** 的价格和持仓。
- `SpeedupQuoteSave.boss_quotes`：**玩家自己写的催工台词**。
- 楼层数、昼夜进度。

**能改的状态（现成接口）**
- `Gamemanager.add_kpi / spend_kpi / add_dollar / spend_dollar`
- `EmployeeManager.hire_employee / fire_employee`
- `Employee.raise_attribute`（永久 +1）/ `force_give_snack_buff` / `go_to_meeting_directly` / `set_custom_name`
- `CultureCenterLogic.switch_culture`
- `BanterManager.trigger_banter`（场景里员工头顶冒吐槽）

## 6. 实装前要处理的坑

- **"见过全部事件"Steam 成就**按事件总数判定（`steam_manager.gd:182-183, 243-244`）。加了条件事件或稀有事件后可能拿不到，要改成"见过 N 个"之类。
- **效率 buff 只在员工开始新一轮工作时读取，且最终效率下限为 1**（`employee.gd:471-476, 1073`）。短时扣效率可能根本扣不下去——这也是"别靠数值当后果"的另一个理由。
- 现有 E21 是代码注释里标明的**"长对话测试"事件**，却在正式抽取池里，也计入成就。
- 结果提示里"（持续 3 分钟）"是写死在 `sidebar_ui.csv` 里的，和 `OfficeManager.EVENT_BUFF_DURATION` 不联动。
